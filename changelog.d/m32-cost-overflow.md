- **Fix (2.0): cost estimates no longer overflow on 32-bit targets or truncate on 64-bit** (M32). calc_mul_cost formed isqrt(p)^3 in usize, which overflows a 32-bit usize from p = 2_643_876 bits (1626^3 > 2^32 - 1; a debug panic, a wrapped estimate in release), and passed p and niter through `as u32` (wrong above 2^32 on 64-bit); series_cost could overflow u64 at large p. Costs are now exact u128 integers clamped to u64::MAX. The argument-reduction count and series length that are used can change. Tests: zenith-float-num/src/common/util.rs, ops/cos.rs, ops/series.rs `cost_overflow_tests`.

- **Fix: `series_cost_optimize` returns the selected candidate.** The best-cost comparison started at `u64::MAX`, which is also a legitimate capped cost, so a capped first candidate was treated as not an improvement. That branch then backed up one `reduction_num_step` from a count that had never advanced, and returned the rejected candidate's `niter` and `m_eff` with the previous count. The first candidate is now evaluated unconditionally and held. A later candidate replaces it only when its cost is strictly lower. The search still stops once the next reduction count would exceed `p.saturating_add(reduction_num_step)`. Returned `niter` and `m_eff` now belong to the selected candidate (previously the rejected next candidate's), which can change which iteration count is used.

- **Tests (2.0): `series_cost_optimize` edgegate mutants are killed** (M32, Vera). A boundary test at `p = 32` visits `next_times == p + step` exactly, so the `>` to `>=` mutant returns the wrong triple; a plateau test at `p = 64` with equal costs at counts 3 and 6 kills the `<` to `==` and `<` to `<=` mutants; the two cos max-precision tests run bounded (30s) so those same mutants fail fast instead of hanging the suite. No production change.
