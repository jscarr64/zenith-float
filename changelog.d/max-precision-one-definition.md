- `MAX_PRECISION` is the fixed `2^60 - 1` (`(1 << 60) - 1`) instead of `min(2^60, usize::MAX / 4) - 1`. On 64-bit targets the value is unchanged (`usize::MAX / 4 = 2^62 - 1 > 2^60`, so the old min already picked `2^60`), so there is no behaviour change. The derivation from `usize` width is gone, together with the 32-bit `2^30 - 2` value (2.0 is 64-bit only, P6). `zenith_float::bound` (`zenith-float-bound/src/precision.rs`) re-exports zenith-float-num's `Precision`, `MIN_PRECISION` and `MAX_PRECISION` instead of defining its own, so there is one definition. Checked by `tools/test_max_precision_single_def.sh`, run in the gate's `unsafe-scan` step.
