`scripts/check_zero_test_targets.sh` (new, internal): fails when any workspace test target runs 0 tests, so an empty target cannot hide in a green run. On main it reported 4 empty targets out of 54: the facade lib unit harness, the `hex_golds` bin, the `integration_tests` target (which only holds tests under the `mpfr-tests` feature), and Doc-tests for the macro crate. The facade lib and the `hex_golds` bin now have small unit tests, `integration_tests` only builds when `mpfr-tests` is on, and macro doctests are off. The script now reports zero empty targets. No library result changes. Spence review fix: the check is now fail-closed — a header with no count, a count with no header, and a target count that differs from the expected 52 (46 for the mpfr-tests pass) all fail, instead of passing silently; the mpfr-tests pass is now checked on x86_64-linux, where integration_tests has tests, and explicitly skipped off that platform, where it is 0 by cfg. The check is now also a step in tools/full_gate.sh, after mpfr-tests-build (not between build-debug and mpfr-tests-build, which tools/test_full_gate_poplog.sh asserts follow directly) so its debug list still reuses the build-debug binaries; previously it lived only in scripts/ci.sh, which set -e stops at the ci_no_name failure before reaching it.
