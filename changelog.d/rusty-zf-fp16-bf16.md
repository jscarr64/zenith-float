- `Ieee16` (IEEE 754 binary16 / FP16) and `Bfloat16` (bfloat16 / BF16) (new, zenith-float 2.0 Slice 1): `u16` bit-pattern boundary types next to `Ieee32` / `Ieee64`, exported from `zenith_float_num` and `zenith_float`. Each has `from_bits` / `to_bits`, `classify` and the `is_*` predicates, constants `ZERO`, `NEG_ZERO`, `NAN` (canonical quiet NaN `0x7E00` / `0x7FC0`), `INFINITY`, `NEG_INFINITY`, `MAX`, `MIN_POSITIVE`, `MIN_POSITIVE_SUBNORMAL`, `to_exact(self, p) -> ExactNum` (exact for every finite pattern, subnormals included, `-0` kept), `from_exact(&ExactNum) -> Self` (ties to even, like `Ieee32::from_exact`) and `from_exact_rm(&ExactNum, RoundingMode) -> Result<Self, Error>` (all seven modes; directed overflow to max finite or infinity by mode; underflow onto the subnormal grid; the sticky bit reads every mantissa word; `RoundingMode::None` refuses an inexact input with `InvalidArgument`). Pure `u16` / integer bit manipulation, no hardware float, no arithmetic on the 16-bit types (boundary conversions only). Tested in `zenith-float-num/tests/fp16_bf16.rs`: all 65,536 patterns of each format decoded against the exact integer relation and round-tripped in every mode at p = 64 and p = 1024; every adjacent pattern pair (max finite / infinity included) rounded at its exact midpoint and at midpoint ± and lo + gap·2^-900 (low-limb sticky) in every mode and both signs; 4,000 pseudo-random 1024-bit operands per format against a binary-search bracket oracle; 2^±10000 extremes; format golds. Additive.
