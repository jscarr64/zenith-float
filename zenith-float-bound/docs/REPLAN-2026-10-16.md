### 3c. After Stage B: which layers really need it

- **L1** (`PLAN:340-390`, current numbering): the only written gate is **P14** (`PLAN:342`, `PLAN:198`). P11 gates constants (PLAN C1 "constant determinism"). P14 is coupled to Option A layer 1a: the Ziv/`round_exact` loops are the "X family", and a written audit of kernels that layer 1a will rewrite is likely invalidated, so the order is 1a first, then P14 [S: `/tmp/zf-logs/zf-pin-items-extract.md` P14 row]. **Answer to "does L1 really need Stage B or only P14 and Stage A items?":** the written gate is P14 plus P11 for the constants, and both are Stage B items; Stage A items alone are not enough for the kernel-mid assertions (TEST_PLAN 15: P14 gates "every L1 function's mid-rounding assertions"). L1 **code and radius rules** (first-order bounds are `Mag` arithmetic, `PLAN:344-349`; domain logic; exact-touch endpoint evaluation) do not need the pin and can be written against an mpmath-supplied midpoint or a stub (a parallelism and quality lever: the real-kernel gate still has to go green); what stays red until B is the green gate on real zf kernels. **How many L1 call sites change:** Rusty's recommendation (provisional, Paul to confirm) is that none do: the L1-called wrappers keep `(&self, p, rm, cc)` and L1 evaluates the same midpoint in `Down` and `Up` with plain borrowed calls (zero copies, no bracketing API, no second owned midpoint). A paired `f_bounds(&self, p, cc) -> (lo, hi)` would be a possible later additive speedup, not in B1.
- **L2a-c** (complex, poly, series, matrices): L2b/L2c need only L0b (see 3b). L2a complex exp/log/sqrt need L1 (exp, ln, atan2, pi), so they inherit Stage B. Complex Rect/Disk arithmetic needs only L0b.
- **L2d specials** (gamma, erf, J0/J1, zeta, and the rest): need L1 constants and exp/ln; those using "zf's correctly rounded value at the midpoint plus a proven bound" (`PLAN:362`) trust zf specials, which are **outside the P14 scope** ("exactly the kernels listed", `PLAN:195`). I could not determine whether any audit of zf specials is planned; if none, L2d needs either certified series in zenith-bound or a new zf audit item (a sequencing question for Rusty, not a scope cut).
- **L3 quadrature**: needs L1 and L2a (ball functions on complex balls, Bernstein-ellipse bound). After L1/L2a.
- **L4**: adaptive precision, root isolation, verified solve (needs L2c), residuals, eigen, ODE (needs ball AD and L1). The shell and the L2c-based solve can be built before B; evaluation of real expressions (`N[expr, d]` is item 1 of the Accumath order, `PLAN` Part F) needs L1.

## 6. Sequencing and parallelism levers (efficiency and quality only)

Each lever below must keep full tests, full P14 findings and a green gate on real zf kernels; none trades correctness or completeness for time. No lever removes scope.

1. **Start Stage-A-free L0b parts and red tests early** (3a). Cost: some rework if Stage A changes P2/P3 shapes (now unlikely, since P1-P3 exist on `wip/option-a`). Goes beyond "L0b may start after Stage A", so it needs Paul's OK.
2. **Build L1-L4 code against a stub backend** (a trait over the handful of zf operations, mids supplied by mpmath in tests): radius rules, domain logic, exact-touch endpoint evaluation, `Tri`, L2b/L2c and the L4 shell need no pin. It cannot test P14, constants or real kernel rounding; the green gate still waits for Stage B. Design owner: Rusty/Paul (CONTRACT 15.1 fixes the by-value/borrowed shapes). Used only because it lets work proceed in parallel and finds API problems early.
3. **Parallel lanes**: L2a-c built on L0b before Stage B; after L1, L2d, L3 and L4 can run in separate lanes. Needs review capacity.
4. **Split Stage B** (`docs/SPLIT-STAGE-B-PROPOSAL.md`): B1 = the Ziv/transcendental family and the `round_exact` pivot for the functions L1 calls; B2 = layers 2-8 and the final `Clone` removal. B2 must not change any B1 public item. It is an ordering for parallelism, and every B1 function still gets its P14 finding and real-kernel gate.
5. **P14 alternative** (`PLAN:195`): `ToEven` plus a proven ≤ 1 ulp bound, or certified kernels in zenith-bound (the "main L1 cost driver", PLAN Part H), removes L1's dependence on the Ziv audit for a kernel found not rigorous. Rusty decides per kernel; it is a correctness choice, not a shortcut.
6. **Cloud agents for heavy runs** (deep fuzz tiers, mutation runs, full gates): takes load off the Pop gate queue without reducing any test tier.
