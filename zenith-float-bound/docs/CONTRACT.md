Notation: `Mag` is an upper bound on a nonnegative real. Conceptually it is `Finite { exp: i64, mant: u64 }` or `Infinity`, but its fields are **private** (decided 2026-10-15, Rusty with Paul and Jeff): a `Mag` is a struct over a private enum and values are built only by `Mag::finite`, `Mag::zero` and `Mag::infinity` (clauses 2.1 and 15.4), so a non-canonical value cannot exist. `Finite { exp, mant }` in this file names that conceptual form. "Rounded up/down" means toward +∞/−∞. `Mag` methods take `&Mag`; `Mag` has no `Copy`, `Clone` or `Hash`, and its `PartialEq`, `Eq`, `PartialOrd` and `Ord` are written by hand and agree (clause 14.5).

## 1. The exponent convention — LOCKED (approved by Jeff, 2026-10-14)

1.1 Everywhere in zenith-float-bound (API docs, `Mag`, the `zf-ball-enc` encoding, traces, tests), a finite nonzero value with exponent `e` and a `k`-bit mantissa `m` (an unsigned integer with its top bit set) means

    value = 0.m · 2^e = m · 2^(e − k),   so value ∈ [2^(e−1), 2^e).

This is zenith-float's `exponent()` convention (`3` is `e = 2`, `m = 0xC000…`). No other convention is used. Where a leading-bit exponent is needed, it is `e − 1` and named `leading_bit_exponent`.

1.2 **Mag:** `k = 64`, `mant ∈ [2^63, 2^64)`, value = `0.mant · 2^exp` = `mant · 2^(exp − 64)`, value ∈ [2^(exp−1), 2^exp). (This replaces the earlier `mant · 2^(exp − 63)`. The fields are unchanged.)

1.3 **`mul_up(a, b)`** (LOCKED with 1.2, from `ee5dbd59`). `P = ma · mb ∈ [2^126, 2^128)` and value = `P · 2^(ea + eb − 128)`.
- If `P ≥ 2^127`: `mant = P >> 64`, `exp = ea + eb`, sticky = low 64 bits ≠ 0.
- If `P ∈ [2^126, 2^127)`: `mant = P >> 63`, `exp = ea + eb − 1`, sticky = low 63 bits ≠ 0.
- If sticky, add 1 to `mant`. A carry to `2^64` gives `mant = 2^63`, `exp + 1`.

1.4 **Half ulp and `smaller_than_half_ulp`** (LOCKED with 1.2, from `ee5dbd59`). For a midpoint with zf exponent `mid_exp` at precision `prec`, ulp = `2^(mid_exp − prec)` and half ulp = `2^(mid_exp − prec − 1)`. A finite Mag is smaller than half an ulp iff `exp ≤ mid_exp − prec − 1`. Boundary set at `mid_exp = 10, prec = 4` (half ulp `2^5`): `exp = 5` with mantissas `{2^63, 2^63 + 1, 2^64 − 1}` is smaller; `exp = 6` is not. Sweep `exp` 3..8 against the independent rational model.

1.5 The encoding's `exp i64` fields (midpoint and Mag) and the trace `e` fields use this convention.

## 2. Zero Mag

2.1 A proven-zero radius is the canonical zero, `exp == 0` and `mant == 0`. It is the only finite `Mag` with `mant < 2^63`. The fields of `Mag` are private (see Notation), so no other value can be observed.
- **Constructor (decided 2026-10-15 on Rusty's review; was O13-W).** `Mag::finite(mant, exp)` denotes `mant · 2^(exp − 64)` (clause 1.1). A mantissa with its top bit set is kept. A mantissa `0 < mant < 2^63` is **normalised**: shifted left by `leading_zeros(mant) = lz`, with `exp` replaced by `exp − lz`. This is exact: the value is preserved and nothing is rounded. If `exp − lz < i64::MIN` the value is below the smallest positive `Mag`, is not representable, and the constructor returns `BoundError::Representation`; it never rounds (clause 3.2 applies to operation results only). `mant == 0` with `exp == 0` is the canonical zero; `mant == 0` with `exp != 0` is **rejected** with `BoundError::Representation` (a proven zero is built with `Mag::zero()`). A rejection is a `BoundError`, never a panic. The decoder does not normalise: it rejects every non-canonical encoding (clause 13).
- **Decoder.** The `zf-ball-enc` decoder does **not** normalise: it rejects every encoding whose mantissa is non-canonical (`0 < mant < 2^63`, or `mant == 0` with `exp != 0`), so that one value has one byte string (clause 13, `identical()`). Earlier text said every constructor and the decoder reject such input; that is superseded: decided, the in-memory constructor normalises (above) and the wire decoder stays strict.

2.2 A radius is zero only when exactness is proven: the inputs are exact and the operation reports that its result is not inexact. zenith-float has no ternary result; its per-operation `inexact()` flag (a `bool`) is the available form, so "an `Equal` ternary" in `docs/PLAN.md` means `inexact() == false`.

2.3 **Order of checks in every Mag operation:** (1) `Infinity` operands and a zero divisor, which have fixed results (clause 14.6); (2) a zero operand, which early-returns before any alignment, normalisation or `leading_zeros`: `add_up(0, b) = b` (built from `b`'s integer parts by `Mag::from_canonical`; see clause O18-C), `mul_up(0, finite) = 0`, `from_exact_num(0) = 0`, `sub_lower(0, b) = 0`, and comparisons with zero go by sign only; (3) the arithmetic. So `mul_up(0, Infinity) = Infinity` (clause 2.4) and `div_up(x, 0) = Infinity` for every `x`, including 0.

2.4 `0 · Infinity = Infinity` for the round-up operation `mul_up`. The round-down operation `mul_lower(0, Infinity)` is the canonical zero (clause 14.6).

2.5 Zero (midpoint 0, radius 0, and both) is a member of every test set.

## 3. Mag underflow (and overflow)

3.1 Exponent arithmetic uses `checked_*` only, never wrapping.

3.2 **Underflow:** a result whose exponent would go below `i64::MIN` rounds **up** to the smallest positive Mag, `Finite { exp: i64::MIN, mant: 2^63 }`. It never becomes zero and never wraps. (A lower-bound helper such as `sub_lower` may return zero, because a smaller lower bound stays sound.)

3.3 **Round-up overflow:** a round-up result whose exponent would go above `i64::MAX` becomes `Infinity`; a round-up result is **never a saturated finite value**, because a saturated finite value would not be an upper bound. NaN or Inf inputs from zf map to `Infinity` when an upper bound is built (`from_exact_num`).

3.4 **Round-down overflow:** a round-down result whose exact value is above the largest `Mag` is the largest `Mag`, `Finite { exp: i64::MAX, mant: u64::MAX }`. `Infinity` is not a lower bound, so it is never returned. A zf NaN or Inf input to a lower-bound conversion (`from_exact_num_lower`) maps to the canonical zero, which is always a sound lower bound.

## 4. Division radius

4.1 For `a = m_a ± r_a` and `b = m_b ± r_b`, the midpoint is `q = m_a / m_b`, rounded to `prec` to nearest (`ToEven`) (O19, DECIDED 2026-10-23, Paul).

4.2 If the divisor touches 0 (`|m_b| ≤ r_b`, decided by `Mag::cmp_exact_num` without converting `r_b` to a zf number), the result is `BoundError::Domain` under every `DomainPolicy`.

4.3 Otherwise

    rad = (r_a + |q|_up · r_b) / (|m_b| − r_b)_down + ε

- numerator: `add_up(r_a, mul_up(qu, r_b))`, where `qu = add_up(from_exact_num(q), ε)` is an upper bound on the **exact** quotient's magnitude (the rounded `q` can be up to `ε` below it);
- denominator: `sub_lower(from_exact_num_lower(m_b), r_b)`, rounded down (positive by 4.2);
- quotient: `div_up`;
- `ε`: `ulp_mag(pre_round_exp, prec)` if rounding `q` was inexact, otherwise 0.

4.4 All radius steps are O(1) Mag operations on u64/u128. Only `q` is computed at `prec`.

## 5. Precision rounding — LOCKED (approved by Jeff, 2026-10-14)

5.1 A midpoint at precision `prec` is rounded to **exactly** `prec` bits (any `prec ≥ 1`, not only a multiple of 64), once, to nearest (`ToEven`); Ball operations take no `rm` (O19, DECIDED 2026-10-23, Paul).

5.2 Exact-bit rounding lives in **zenith-float** (PLAN C1 **P15**, tied to zf defect 6). zenith-float-bound **never** re-chops or re-rounds a zf result to a smaller precision, and has no chop fallback, because a second rounding of an already-rounded value is double rounding.

5.3 If the zf 2.0.0 defect-6 fix delivers exact-bit rounding, P15 folds into 2.0.0; otherwise it stays in 2.1. Either way, L0 does not start until it is green on Pop.

## 6. Value model (PLAN Part L 1)

6.1 A `Ball` denotes the closed set `[mid − rad, mid + rad]` of reals. `rad = Infinity` denotes all reals; its canonical form has `mid = +0`.

6.2 A NaN or infinite midpoint is never stored. An operation that would produce one returns `BoundError` (or, for an unbounded or overflowed result, the all-reals ball of clause 6.1 as `Ok`, clause 6.4), never a finite ball that excludes a possible value.

6.3 **Signed zero.** A −0 midpoint (for example exact cancellation under `Down`) is normalised to +0 at the ball boundary, in every constructor and every op result, so `identical()` and the encoding see one zero.

6.4 **Result shape (O1, DECIDED 2026-10-16, Paul under Jeff's delegation, Rusty recommended).** Every L0b, L1, L2 and L3 operation returns `Result<Ball, BoundError>` (or `Result<X, BoundError>` for a non-ball result). There is no `Enclosure` type and no `Indeterminate` variant. The three outcomes mean: `Ok(ball with rad = Infinity)`: the true result is mathematically unbounded or overflowed (O2), for example `Clip` over an unbounded image; this is a sound enclosure returned as `Ok`. `Err(BoundError::Resource)`: the engine gave up (budget, iteration or precision cap). `Err(Domain | InvalidArgument | Representation)`: the question itself is invalid. `Ball::is_informative(&self) -> bool` is false iff `rad = Infinity`; the user-facing layer (L4, Accumath) must check it and never print or use a midpoint of an `Infinity` ball. `floor`, `ceil` and `sgn` do not return a `Ball`: they return a small enum `Decided(value) | Undecided` (the names are the implementer's choice) inside `Result<_, BoundError>`. A test helper `is_refusal(&result)` is one function: refusal means `Err(..)` or an `Ok` ball with `rad = Infinity`, as each row states.

6.5 **Ball canonical form (D15 a, b, e; DECIDED 2026-10-16, Paul under Jeff's delegation, Rusty recommended).** (a) `Ball` fields are **private**; construction goes through checked constructors. Every operation **output** has a `mid` of at most `prec` bits, with the rounding error absorbed in `rad` (this follows from clause 5 and PLAN C5.1). An exact constructor input wider than `prec` either keeps `rad = 0` exactly (the `mid` stays exact) or is rounded **with** `rad`; it is never silently truncated. (b) Comparisons and `Tri` ignore `prec`. `union` and `intersect` results use `prec` = the maximum of the two. `identical(&self, &Ball) -> bool` is structural and **includes** `prec`; it returns `bool`, not `Tri` (O20, DECIDED 2026-10-23, Paul). (e) `rad = 0` for an exact `sqrt`, `exp(0)` or `ln(1)` only when zenith-float's per-operation `inexact() == false` proves it (clause 2.2; zenith-float P9 and P15 are done).

## 7. Invariant (PLAN Part L 2)

7.1 For every guaranteed op `f` and inputs `x_i ∈ X_i`, `f(x_1, …) ∈ f_ball(X_1, …)`, or the op returns `BoundError`. Nothing else is allowed. (The all-reals ball satisfies the first alternative; clause 6.4.)

## 8. Precision and exponent range (PLAN Part L 3 and 4; precision rounding itself is clause 5)

8.1 `prec` is at least 1 and shapes only the midpoint. `prec` is `u32` at the `Ball` API (decision O17-W); a `prec` of 0 is rejected with `BoundError::InvalidArgument` before zenith-float is called, because zenith-float accepts `p = 0` and then returns an exact zero for a nonzero sum. A `Ball` stores the **requested** `prec` and never reads it back from zenith-float, which reports the 64-bit container as `precision()` and rounds exact bits at small `p`. The radius is always a `Mag` (64-bit mantissa, `i64` exponent). zenith-float's precision type is `usize`, so `prec: u32` becomes `usize` only through `usize::try_from` (a failure is `BoundError::Resource`), never `as`. Ball operations take `prec` but no `RoundingMode` (O19, DECIDED 2026-10-23, Paul); the `RoundingMode::None` rejection and the `prec`-to-`usize` rule apply at the zenith-float scalar level, inside zenith-float-bound, only.

8.2 Radii: `Mag` exponents are `i64`; beyond that the radius is `Infinity` (clause 3).

8.3 Midpoint exponents are zenith-float's `EXPONENT_MIN..=EXPONENT_MAX`. (The 32-bit-target sentence of PLAN Part L 4 is dropped, decision O3: zenith-float's `Exponent` is `i64` and `EXPONENT_MAX`/`EXPONENT_MIN` are ±(2^62−1) on every target (O21, pinned at zenith-float `829f112`), so no target refuses a midpoint on range grounds.) Tests: `exponent_min_max_are_i64_62_bit` and `radius_below_exponent_min_rounds_out_to_smallest_mag` (a radius below the range rounds outward to the smallest positive `Mag`, 10.4) in tests/harness/slice_arith.rs.


## 9. Rounding and radius rules (PLAN Part L 5 and 6; division is clause 4)

9.1 **Rounding.** The midpoint is rounded once to `prec` to nearest (`ToEven`) from an exact or fully accounted value (clause 5); there is no caller `rm` (O19, DECIDED 2026-10-23, Paul). The radius is rounded **up** at every step. No rounding error is ever dropped. Directed modes are used internally only (radius and endpoint bounds) and never change containment. `RoundingMode::None` truncates and is never used in a bound path.

9.2 **Radius rules.** A radius is nonnegative. It is zero only when exactness is proven (clause 2.2). A zero radius early-returns through every Mag operation (clause 2.3).

9.3 **Add:** `(m + n) ± (r + s + ε)`. **Mul:** `m·n ± (|m|·s + |n|·r + r·s + ε)`. Every term and every sum is evaluated with `add_up`/`mul_up`.

9.4 **ε** is zero if rounding the midpoint was exact (`inexact() == false`), and otherwise depends on the rounding mode, with an **exhaustive `match` over `RoundingMode` and no wildcard arm** (decisions O4 and O5, Rusty, 2026-10-15). Since (O19, DECIDED 2026-10-23, Paul) a Ball midpoint is always rounded with `ToEven`, so its ε is the `half_ulp`; the full table stays normative for the internal `ulp`/`half_ulp` helpers and any internal directed rounding:
- **Nearest modes** `{ToEven, ToOdd}`: ε is `half_ulp` (`2^(e − prec − 1)`). A half ulp is sound for the nearest family only.
- **Directed modes** `{Up, Down, ToZero, FromZero}`: ε is the full `ulp_mag(e, prec)` (`2^(e − prec)`).
- **`RoundingMode::None`**: rejected with a `BoundError` at the zenith-float scalar level (no Ball API takes a mode, O19); it truncates and is never used in a bound path (clause 9.1).
- `e` (`pre_round_exp`) is zenith-float's `exponent()` of the **rounded result** (clause 1.1 convention); zenith-float's pre-round exponent (the former P7) is not required, because the ulp at the rounded exponent is at least the ulp at the pre-round exponent, so the bound stays sound. The subnormal clamp `max(e, MIN_NORMAL_EXPONENT)` lives in the L1 caller, not in `ulp_mag`/`half_ulp`. A **zero result** maps to `EXPONENT_MIN` (zenith-float's `exponent()` of zero is 0, which would make ε wrongly large). For a subnormal result `exponent()` reports `EXPONENT_MIN`.

## 10. Domains and special values (PLAN Part L 7)

10.1 There is one `DomainPolicy { Strict, Clip }`. Every op with a restricted domain (sqrt, the log family, asin/acos, acosh, atanh, `tan` (clause 10.2d), `pow` with a non-integer exponent, …) applies it the same way and takes it as an **explicit last parameter** (clause 15.1; O6, DECIDED 2026-10-16, Paul under Jeff's delegation, Rusty recommended). `Strict` exists as `impl Default for DomainPolicy` only; callers still pass the policy explicitly; there are no paired `foo()` / `foo_policy()` forms. `DomainPolicy` is `#[non_exhaustive]` (still exactly `Strict` and `Clip`; a later variant is not a breaking change). **Solver options (options unit, DECIDED 2026-10-23, Paul):** `SolveOpts { refine_steps: usize }` (default 2) and `EigOpts { max_sweeps: usize, cluster: bool }` (default 64, `true`) live in `policy` next to `DomainPolicy`; both are `#[non_exhaustive]` with `impl Default`, so callers build them from `Default::default()` and set fields, never with a struct literal.

10.2 **`Strict`** returns `BoundError::Domain` if any point of the input ball lies outside the domain. **`Clip`** encloses `f` over the intersection of the ball with the domain, and returns `Domain` only if that intersection is empty or is a single pole.

**10.2a to 10.2e (DECIDED 2026-10-16, Paul under Jeff's delegation, Rusty recommended; Cassie's text accepted with the fixes below; normative and testable).** They refine 10.2 and close O11-C, O12-C, O13-C and O14-C. Basis for every item: a ball is never silently wrong; "cannot tell" is either loud (an error) or provably sound (an all-reals ball).

10.2a **Unbounded image (O11-C, decided).** If the intersection of the ball with the domain is nonempty and `f` is unbounded on it (`ln` or `log` over `(0, b]`, `atanh` toward ±1, `tan` across a pole), `Clip` returns `Ok` with `rad = Infinity` (the all-reals ball of clause 6.4 and O2), never a finite ball and never `Domain`.

10.2b **Domain table (O12-C with 10.2c, decided).** Closed endpoints: `asin` and `acos` on `[-1, 1]`, `acosh` on `[1, inf)`, `sqrt` on `[0, inf)` (**fix: `sqrt` was listed as open; 0 is in `[0, inf)`**). Open endpoints: `atanh` on `(-1, 1)`, `log`/`ln` on `(0, inf)`. `tan` excludes `π/2 + k·π`. `pow` with a non-integer exponent needs `x > 0` in v1 (a conservative refusal: it refuses `pow(0, 2.5)` where the right answer is 0; a later refinement may let `Strict` accept `x ≥ 0` when the exponent ball is exactly positive). `Strict` returns `Domain` iff some point of the ball is outside the domain, so a ball reaching a closed endpoint (for example `|m| + r = 1` for `asin`) is inside it. For `sqrt` this means `Strict` returns `Domain` iff `m − r < 0`, decided exactly; at `m − r = 0` the result is a ball built from the endpoints (`[0, sqrt_up(m + r)]`), finite and sound; `rad = Infinity` is not used (D15 d; settles M9 and K16 of `docs/TEST_PLAN.md`). Note: `atanh(±1)` and `log 0` are real exclusions; `asin(±1)`, `acos(±1)` and `acosh(1)` are in the closed domain.

10.2c **Exact inside-the-domain test (Rusty's condition, O12-C, decided).** Decide "inside the domain" with an **exact** comparison (`cmp_exact_num` style, as in clause 4.2), never with `add_up`, which would call an exact touch outside: for `asin`, `acos` and `atanh` `|m| + r ≤ 1` (closed) or `|m| + r < 1` (open) per endpoint type; for `acosh` `m − r ≥ 1` (**fix: the `|m| + r` formula does not apply to `acosh`**). **Requirement on L1 (not a change of the text above):** for monotone functions (`asin`, `acos`, `acosh`, `sqrt`, `atanh` in its interior, `ln`) an exact touch is evaluated from the endpoints, which gives a finite, informative, sound ball. `rad = Infinity` is used only where the image is truly unbounded (`atanh` toward ±1, `ln` toward 0, `tan` across a pole) or as a documented fallback when no proven one-sided bound exists.

10.2d **`tan` (O14-C, decided).** `tan` joins the clause 10.1 list and takes a `DomainPolicy`. `Strict` returns `Domain` when the ball contains `π/2 + k·π`, decided with sound directed bounds of `π`, not one rounded `π`; "cannot exclude" counts as "contains". Where argument reduction cannot be done soundly (for example `|m| ≈ 1e600000000`) the result is `Domain` under `Strict` or the all-reals ball under `Clip`, never a guess. `Clip` returns `Ok` with `rad = Infinity`. The "single pole" `Domain` case of 10.2 never occurs for `tan`. Near the pole boundary either `Domain` or a sound ball is allowed. A sound ball must really contain the exact `tan`, checked at sample points against mpmath goldens. Tests accept both outcomes but never an unsound ball.

10.2e **`0^0` (O13-C, DECIDED 2026-10-16, Paul under Jeff's delegation, Rusty recommended; zenith-float probe CONFIRMED by Rusty 2026-10-16).** `0^0 = 1` on the **integer-exponent path only**. `powi`, or a real-exponent `pow` whose exponent ball has `rad = 0` and value 0, returns exactly `1` with `rad = 0` for every base, including 0 and a base ball containing 0. `pow(x, 0)` for `x ≠ 0` is exact. For a real-exponent `pow` with a base ball containing 0: `Strict` returns `Domain`; `Clip` returns the all-reals ball (`rad = Infinity`) when the exponent can be negative, otherwise a hull that includes the **whole** limit range `[0, 1]` (the limit of `x^y` at `(0, 0)` depends on the path), never `1 ± 0`. Probe: zenith-float's `pow`, `powi` and `powsi` return exactly 1 for `0^0` and `(-0)^0` with `inexact() == false` in every rounding mode, on `wip/option-a` and 1.0.12 (Rusty). **Tests may assert the integer-exponent path `0^0 = 1`. No test may assert any zenith-float behaviour for the real-exponent, base-contains-0 case beyond this text** (zenith-float has sign and infinite-exponent special-value bugs, W6, being fixed on the float side; a `Ball` never feeds an `Inf` into zenith-float).

10.3 Division by a ball touching 0 returns `Domain` under both policies (clause 4.2).

10.4 **Underflow:** the radius absorbs the lost value and is never zero; `Mag` exponent underflow rounds up to the smallest positive `Mag` (clause 3.2). `0 · Infinity` in radius arithmetic is `Infinity` (clause 2.4). A round-up overflow never saturates (clause 3.3). **Midpoint overflow (decision O2, Rusty): one fixed behaviour, no caller parameter and no policy field.** A zenith-float result `r` of a midpoint operation at precision `prec` under `rm` has **overflowed** iff `r` is `Inf`, or `r` is `NaN` with `err() == ExponentOverflow(_)`, or (`r.inexact()` and `r.exponent() == EXPONENT_MAX`). The third form exists because zenith-float saturates to a finite `max_value(p)` flagged inexact when the rounding direction is toward zero (`ToZero` always; `Down` when the exact result is positive; `Up` when it is negative), and returns `±Inf` with the inexact flag not set for every other mode and direction. The test is conservative: an inexact result in the top binade is reported as overflow even if none happened (sound, costs tightness only). A `NaN` is mapped by its error kind: `ExponentOverflow` is the overflow behaviour, `DivisionByZero` is `Domain`, `InvalidArgument` is `InvalidArgument`, `MemoryAllocation` and `PrecisionRetryExhausted` are `Resource`. **On overflow the `L1` ball is the all-reals ball** (`mid = +0`, `rad = Infinity`, clause 6.1), **not** a `BoundError::Overflow`; there is no `Overflow` variant. O1 is decided as `Result<Ball, BoundError>` with "uninformative is `rad = Infinity`" (clause 6.4), so the all-reals ball is returned as `Ok`. Either way a ball with a NaN, Inf or saturated midpoint is never stored (clause 6.2). The domain policy is an explicit last parameter (clause 10.1, 15.1; O6 decided).

## 11. Exactness (PLAN Part L 8)

11.1 `from_integer` and `from_rational` are exact when the denominator is a power of 2 and the value fits `prec`; otherwise they return a correctly enclosed ball. `is_exact` is true only with proof.

## 12. Correctness vs tightness (PLAN Part L 9)

12.1 A correctness failure (a result that excludes a possible true value) is a P0 bug. A tightness miss is measured as an overestimation ratio against the oracle's radius and tracked; it is a performance bug. This clause sets no numeric tightness thresholds; each test states its own (D15, decided 2026-10-16).

## 13. Determinism (PLAN Part L 10)

13.1 The same `(op, inputs, prec, version)` gives the same bytes on every supported target, build profile and thread count.

13.2 **Decoder rejects non-canonical input (D15 c, DECIDED 2026-10-16, Paul under Jeff's delegation, Rusty recommended).** The decoder rejects: a nonzero `mid` with `rad = Infinity`; a `Mag` mantissa without its top bit (when nonzero); trailing zero bytes; reserved tags. One value has exactly one encoding. Tests: `encode ∘ decode ∘ encode` is the identity for every constructor; a byte-mutation sweep (every single-byte mutation of a valid encoding either decodes to a value whose re-encoding is that same mutated byte string, or is rejected).

## 14. Mag operations (L0; from PLAN C6 and `docs/PLAN.md` Part D, L0 file plan)

All of this section is integer-only (`u64`/`u128`/`i64` and wider integers in tests). For a finite `Mag` `x`, `value(x)` is defined by clause 1.2, and the canonical zero by clause 2.1. "Exact" means the real number the operands denote.

14.1 **Round-up operations** `add_up`, `mul_up`, `div_up`, `sqrt_up`: the result is the smallest representable `Mag` that is ≥ the exact result (rounding to 64 significant bits, toward +∞), subject to clauses 2 and 3. This is what clause 1.3 states for `mul_up`. Where the exact result is not a `Mag` value (it exceeds the exponent range), clause 3.3 applies. A round-up result is therefore never below the exact result and its predecessor `Mag` is below the exact result (that is the "within one Mag-ulp" tightness property).

14.2 **Round-down operations** `sub_lower`, `mul_lower`, `div_lower`, `sqrt_lower`: the result is the largest representable `Mag` that is ≤ the exact result (rounding to 64 significant bits, toward −∞), **with one exception, stated as an iff: the result is the canonical zero if and only if the exact result is below the smallest positive `Mag`, `min_pos = Finite { exp: i64::MIN, mant: 2^63 }`** (this covers an exact zero, `sub_lower(a, b)` with `a ≤ b`, and an underflow; a lower bound of zero is always sound). An exact result above the largest `Mag` gives the largest `Mag` (clause 3.4). Round-up underflow is the opposite case: it gives `min_pos`, never zero (clause 3.2).

14.3 **`add_up(a, b)`** (PLAN C6): align to the larger exponent; shifted-out bits go to a sticky bit; add with carry (a carry renormalises by one and its lost bit also goes to sticky); if sticky, add 1 at the last place and renormalise. If the exponent gap is ≥ 64 and the smaller operand is nonzero, the result is the larger operand plus one unit in its last place (which is the round-up result by 14.1).

14.4 **`div_up`/`div_lower`** are computed on `u128 / u64` with a sticky remainder; **`sqrt_up`/`sqrt_lower`** by the integer square root of a `u128` with the exponent parity fixed first (PLAN L0 file plan). The results are those of 14.1 and 14.2.

*Implementation note (not normative; it states one derivation that meets 14.1 and 14.2, checked against the independent integer oracle in `tests/model/direct.rs`).* **Division** of finite nonzero `a` by `b`: `n = ma << 64` (a `u128`), `q = n / mb ∈ [2^63, 2^65)`, sticky = `n % mb != 0`. If `q < 2^64` the result is `mant = q`, `exp = ea − eb`; otherwise `q` has 65 bits, so `mant = q >> 1` (the lost bit joins the sticky) and `exp = ea − eb + 1`. **Square root**: if `ea` is even, `N = ma << 64` and `exp = ea / 2`; if `ea` is odd, `N = ma << 63` and `exp = (ea + 1) / 2`; `r = isqrt(N)` has its top bit set, sticky = `r·r != N`. For a round-up result with sticky, add 1 to `r` (or to the quotient mantissa); a carry to `2^64` renormalises to `mant = 2^63` with `exp + 1`, and an exponent that leaves the `i64` range follows clauses 3.2 to 3.4. All exponent arithmetic is `checked_*` or done in a wider integer (clause 3.1).

14.5 **Order (decided 2026-10-15, Rusty with Paul; was O8).** `Mag` implements `Ord` by hand: `cmp(&self, &Mag) -> Ordering` is the trait method, not an inherent `cmp` (an inherent `cmp` trips clippy's `should_implement_trait` and `#[allow]` is banned). `PartialEq`, `Eq` and `PartialOrd` are also written by hand and follow `Ord` (`eq` is `cmp == Equal`, `partial_cmp` is `Some(cmp)`); none is derived, because the derived order would place the canonical zero by its exponent field. The order compares denoted values: the canonical zero is the **least** element and all zeros are equal; two finite nonzero values compare by `(exp, mant)` lexicographically; `Infinity` is the **greatest** element and equal only to itself. There is no NaN, so the order is total and reflexive. Caveat: `Mag: Ord` is the order of bounds, not of numbers; a soundness decision must not rest on `==` between two `Infinity`s meaning "the same number".

14.6 **Corner operands (decided 2026-10-15, Rusty; was O7).**
- **Rule R-UP** (round-up operations; no finite value would be a sound upper bound): an `Infinity` operand of `add_up`, `mul_up`, `div_up` or `sqrt_up` gives `Infinity`, including `mul_up(0, Infinity)` (clause 2.4) and `div_up(Infinity, b)`. A zero divisor gives `Infinity`: `div_up(x, 0) = Infinity` for every `x`, and `div_up(0, 0) = Infinity`. `div_up(0, b)` for a finite nonzero `b` is zero (clause 2.3).
- **Rule R-DOWN** (round-down operations; zero is always a sound lower bound): an `Infinity` operand of `sub_lower`, `mul_lower`, `div_lower` or `sqrt_lower` gives the canonical zero, including `mul_lower(0, Infinity)`; `div_lower(x, 0)` is the canonical zero.
- **Overflow and underflow:** a round-up overflow is `Infinity` (clause 3.3); a round-down overflow is `Finite { exp: i64::MAX, mant: u64::MAX }` (clause 3.4); a round-up underflow is `min_pos` (clause 3.2); a round-down underflow is the canonical zero (clause 14.2).
- **`Mag::sub_up` does not exist at L0** (decision O16-W, decided: none). Nothing in the L0 or L1 float path needs it: the abs hull math uses `add_up` and division uses `sub_lower` for the denominator (clause 4.3). If it is ever needed, `sub_up(a, b)` is the smallest `Mag ≥ max(a − b, 0)`, so it is zero for `a ≤ b`.

14.7 **`ulp_mag(pre_round_exp, prec)`** is `2^(pre_round_exp − prec)`, i.e. `Finite { exp: pre_round_exp − prec + 1, mant: 2^63 }` (clause 1.2), with `pre_round_exp` in the `0.m·2^e` convention of clause 1.1. **`half_ulp(mid_exp, prec)`** is `2^(mid_exp − prec − 1)`, i.e. `Finite { exp: mid_exp − prec, mant: 2^63 }`. **`smaller_than_half_ulp(&Mag, mid_exp, prec)`** is the predicate of clause 1.4. **Out-of-range exponents.** `ulp_mag` and `half_ulp` are Mag *values*, so an exponent below `i64::MIN` follows clause 3.2 (round up to the smallest positive Mag, `Finite { exp: i64::MIN, mant: 2^63 }`) and one above `i64::MAX` follows clause 3.3 (`Infinity`). The *predicate* `smaller_than_half_ulp` is not a Mag value and clause 3.2 does not apply to it: it evaluates `exp ≤ mid_exp − prec − 1` in checked or wider (`i128`) arithmetic, never wrapping, and never rounds the threshold up to `i64::MIN`. When the threshold `mid_exp − prec − 1` is below `i64::MIN`, every nonzero Mag is at or above the smallest positive Mag, so the predicate is false for every nonzero Mag (rounding the threshold up to `i64::MIN` would wrongly make `Finite { exp: i64::MIN, .. }` "smaller"). For the canonical zero the predicate is true (value 0 is below any half ulp, whatever `mid_exp` is), and for `Infinity` it is false (decision of Paul and Rusty, 2026-10-15, part of O10; the predicate must never be used to drop a radius). Tests: `half_ulp` at `mid_exp` from `i64::MIN` to `i64::MIN + prec + 1`, and `smaller_than_half_ulp` near `i64::MIN` against the rational model, in `tests/mag/ulp.rs`. The subnormal clamp `eff_exp = max(pre_round_exp, MIN_NORMAL_EXPONENT)` of PLAN G3 belongs to the L1 caller (`mid_rounding_error`), not to `ulp_mag` (decision O5, clause 9.4). The signatures `ulp_mag(i64, u32) -> Mag`, `half_ulp(i64, u32) -> Mag` and `smaller_than_half_ulp(&self, i64, u32) -> bool` are decided (O10); `prec: u32` follows clause 8.1, and a zenith-float exponent is already `i64` (O21). `ulp_mag(e, 0)` and `half_ulp(e, 0)` are outside clause 8.1 (`prec ≥ 1`) but total: the formulas above hold for every `u32` `prec` including 0, with the out-of-range rules above (`ulp_mag(i64::MAX, 0)` is `Infinity`). `Ball` operations never pass `prec = 0` (clause 8.1, `InvalidArgument`); the two `prec = 0` tests pin the Mag formula only and do not mean zenith-float supports `p = 0`. The formulas are exact in `i128` for every `u32` `prec`, including `prec ≥ 2^31`, and `ulp_mag(i64::MAX, prec ≥ 1)` is the finite `Finite { exp: i64::MAX − prec + 1, mant: 2^63 }`, not `Infinity`.

## 15. API shapes (PLAN C5, as far as they are settled)

15.1 Ball operations take an explicit `prec: u32` and **no `RoundingMode`** (O19, DECIDED 2026-10-23, Paul): the midpoint rounds to nearest (`ToEven`) and the radius rounds outward and absorbs the error. They return `BoundResult<Ball>` (`= Result<Ball, BoundError>`, clause 6.4), except `neg`, which is exact and infallible. An operation with a restricted domain (clause 10.1, including `tan`) takes an explicit `DomainPolicy` as its last parameter (O6, decided; `Strict` is `Default::default()` only; no paired forms); an operation without one (add, sub, neg, abs, mul, mul_2exp, sqr, powi, hypot, and div/inv, whose divisor-touches-0 rule is the same under both policies, clause 10.3) does not. **Ownership (decision O9, Rusty; amended 2026-10-24, Jeff, S1 borrowing unit option B): `sqr`, `inv`, `sqrt`, `hypot`, `powi` and `abs` borrow every operand (`&self`, second operand `&Ball`), because each maps onto a borrowing zenith-float op at the 829f112 pin (`mul_full_prec` with its per-operation `inexact()` flag for `sqr`, `reciprocal`, `sqrt`, `hypot`, and `ExactNum::from(±1).mul` for `abs`) with no copy and no `*_ref` call; `add`, `sub`, `mul`, `mul_exact`, `div`, `mul_2exp` and `neg` take the first operand by value and borrow the second**, matching zenith-float's Rule R shape `add(self, &Self, p, rm)` (zenith-float-bound passes `ToEven` internally). Those seven move to borrowing once zenith-float provides borrowing correctly-rounded ops (open with Rusty); until then a borrowing form would need a `*_ref` call or a copy, both ratcheted; `Mag` methods take `&Mag` for every operand; `from_exact_num` reads the magnitude of a zenith-float number through `as_raw_parts()`. **`neg`, `abs`, `mul_2exp` (decision O14-W):** inherent methods on `Ball`; `neg` and `mul_2exp` take `self`, `abs` takes `&self` (amended 2026-10-24, option B; nothing is cloned). `neg` is `impl core::ops::Neg for Ball` (an inherent `neg(self)` trips clippy's `should_implement_trait`), takes no `prec` (and, like every Ball op, no `rm`), and is exact; a −0 midpoint becomes +0 (clause 6.3). `abs(&self, prec) -> BoundResult<Ball>` takes `prec`: for a ball straddling 0 the image is `[0, |m| + r]`, whose midpoint needs rounding, and the radius side uses `add_up`, not `sub_up`. `mul_2exp(self, k: i64, prec) -> BoundResult<Ball>` takes `prec` (`k: i64` is zenith-float's `Exponent` at the 829f112 pin, whose range `EXPONENT_MIN..=EXPONENT_MAX` is ±(2^62−1) (O21, 8.3); `k` may be any `i64`, and a result outside that range over- or underflows as below; the earlier `i32` predates zenith-float's i64 exponents, changed 2026-10-24 by S1, 16.S1.10): it is exact unless the midpoint over- or underflows (clause 10.4), and its radius side is the total `r · 2^k` rounded up (S1 keeps it private in `src/arith.rs` as `mag_mul_2exp_up(&Mag, i64) -> Mag`, since `src/mag` is not S1's file) with a checked exponent (overflow is `Infinity`, underflow is the smallest positive `Mag`, clauses 3.2 and 3.3). The `*_ref` forms of zenith-float are a last resort and are ratcheted.

15.2 `Ball` has no `PartialEq`/`PartialOrd`, no `From<Ball> for ExactNum`, no `From<f64>`, and no `refine`. Equality of representations is `identical(&self, &Ball) -> bool`; value questions use the `Tri` comparisons, and `contains` and `overlaps` also return `Tri` (O20, DECIDED 2026-10-23, Paul). **`Tri` (decision O15-W)** has the variants `{True, False, Unknown}` and is exhaustive (not `#[non_exhaustive]`; API freeze F2): the three values are the complete set and callers may match without a wildcard. `True` or `False` is returned only when decided by **exact endpoint comparison** (D14, decided 2026-10-16, Paul under Jeff's delegation, Rusty recommended; Cassie's table is **normative**): `m1 − m2` is compared against `r1 + r2` with exact arithmetic or an exact comparison primitive (`Mag::cmp_exact_num` of clause 4.2 is the starting point; add an exact diff-compare if needed), never with `add_up` or another rounded sum; the same primitive serves clause 10.2c. Any doubt is `Unknown`. Exact equality is `True` only when both radii are proven zero (clause 2.2) and the midpoints compare equal. Any comparison with an `Infinity` radius is `Unknown`, even a ball against itself. Touching edges: `le` and `ge` with touching edges are `True`; `lt`, `gt` and `eq` with touching edges are `Unknown`; an exact point on a ball edge is `True` for `le`/`ge` (on the correct side) and `Unknown` for `lt`/`gt`/`eq`; a point in the interior is `Unknown`; exact 3 against exact 3 is `True` for `eq`; disjoint balls are `False` for `eq`. Comparisons ignore `prec` (clause 6.5). `lt`, `le`, `gt`, `ge`, `eq` and `ne` are defined from one primitive.

15.3 `BoundResult<T>` is `Result<T, BoundError>` (O1, decided 2026-10-16; clause 6.4). There is no `Enclosure` type. "Valid but uninformative" is an `Ok` ball with `rad = Infinity` (`Ball::is_informative()` is false); overflow reporting (clause 10.4) uses the same all-reals ball.

15.4 **`Mag` construction and access (decided 2026-10-15, Rusty with Paul and Jeff).** `Mag` is a struct with private fields (Notation), with `Mag::finite(mant: u64, exp: i64) -> Result<Mag, BoundError>` (clause 2.1: keeps a canonical mantissa, normalises `0 < mant < 2^63`, rejects `mant == 0` with `exp != 0` and an exponent below `i64::MIN`), `Mag::zero()`, `Mag::infinity()`, and read accessors `exp(&self) -> Option<i64>`, `mant(&self) -> Option<u64>` (`None` for `Infinity`), `is_zero(&self)`, `is_infinity(&self)`. Tests build values only through these constructors. The `Option` shape of the accessors is decided (O12-W): zero is `Some(0)` and `Some(0)`, `Infinity` is `None` for both. The `BoundError` variant set is decided (O11-W, Decisions table); the constructor's rejection is `BoundError::Representation`.

15.5 **Allocation failure (API freeze F7, behaviour contract).** Storage that zenith-float-bound itself allocates in proportion to a caller's size (container storage: `BallArray::zeros` today, and every later container or LA op) is reserved with `try_reserve`/`try_reserve_exact`; when it cannot be allocated the op returns `Err(BoundError::Resource { .. })` and does not abort. A shape whose element count overflows `usize` is `InvalidArgument` instead. Out of scope: allocations inside zenith-float (one bignum's limbs) and the shrink in `Vec::into_boxed_slice` of a caller-supplied `Vec`; those follow Rust's global allocator (abort on OOM).

15.6 **Container and linear-algebra op signatures (API freeze F8).** Every container or LA op that computes balls (elementwise ops, norms, products, solves, factorizations, eigen) takes an explicit `prec: Precision` and **no `RoundingMode`** (the clause 15.1 rule: midpoints round to nearest internally, radii outward), and returns `BoundResult<_>`. Iteration budgets come from the `SolveOpts`/`EigOpts` option structs; running out of budget is `NotConverged`. Pure accessors (`shape`, `rank`, `len`, `get`, `nrows`, `ncols`, `as_slice`) take no `prec` and return plain values or `Option`.

### Slice S1 (`src/arith.rs`)

Owner: slice S1 (Spence). Code: `src/arith.rs`. Tests: `tests/harness/slice_arith.rs`. Mutants 200-299.

- **16.S1.1 Propagation.** `add`/`sub`: `round(m ± n) ± (r + s + ε)`. `mul`: `round(mn) ± (|m|s + |n|r + rs + ε)`. Every `Mag` step rounds up; every midpoint is the zenith-float operation at `prec`, `ToEven` (O19). `prec` outside `MIN_PRECISION..=MAX_PRECISION` is `InvalidArgument`; a midpoint overflow is `Ok(all reals)` (10.4).
- **16.S1.2 ε.** Zero for an exact midpoint. `half_ulp(e, prec)` for an inexact midpoint with exponent `e > EXPONENT_MIN`. For a zero or bottom-binade (subnormal) result that is inexact, or whose exact value was lost below the range, ε is the bottom ε `Mag::ulp_mag(EXPONENT_MIN, 0)`, so an underflow is never a silent flush. A shallow underflow that zenith-float keeps exactly (leading zero bits at `EXPONENT_MIN`) stays exact with radius 0.
- **16.S1.3 neg.** `-(m ± r) = (-m) ± r`: exact and infallible, and a −0 midpoint becomes +0.
- **16.S1.4 mul_exact.** `(m ± r)·c = round(mc) ± (|c|r + ε)` for an exact scalar `c`. A NaN or infinite `c` is `Representation`.
- **16.S1.5 sqr.** `round(m²) ± (2|m|r + r² + ε)`. The square is taken at full precision with the inexact flag cleared first, so an underflow inside the square sets the lost flag and forces ε (16.S1.2). This bound is tighter than `mul` of the ball with itself.
- **16.S1.6 powi.** `n == 0` is exactly `1 ± 0` for every ball, including one that contains 0 (10.2e). Otherwise, left-to-right binary exponentiation with `sqr`/`mul` at `prec + 64` bits (capped at `MAX_PRECISION`), then one final rounding to `prec`. A non-informative intermediate gives all reals. `powi_exact_input_within_one_ulp` checks that an exact input's power stays within one ulp, which needs the guard bits.
- **16.S1.7 sqrt.** The domain is closed, `[0, inf)` (10.2b). With `lo = m − r` and `hi = m + r` decided exactly: `lo > 0` gives `round(√m) ± (r / √m↓ + ε)`, and `lo == 0` gives the endpoint ball `[0, √hi↑]`. `lo < 0` is `Domain` under `Strict`. Under `Clip`, `hi < 0` is `Domain`, `hi == 0` is exactly 0, and `hi > 0` gives the endpoint ball. The all-reals input is `Domain` (Strict) or all reals (Clip). `Resource` applies if the sign of `m − r` cannot be decided. For `m < 0 < m + r` under `Clip`, `hi` is `m + r` computed exactly (`r` itself only when `r` is outside zenith-float's range). Tests: `sqrt_rows`, `sqrt_lo_zero_is_the_endpoint_ball`, `sqrt_clip_negative_mid_hull_is_m_plus_r`, `sqrt_radius_is_at_least_r_over_sqrt_m`, `containment_sqrt`.
- **16.S1.8 div, inv, hypot (zenith-float R13).** `div(self, &Ball, prec)`: when the divisor `n ± s` excludes 0 (`|n| > s`, decided exactly as in 16.S1.7), `round(m / n) ± ((|m| s + |n| r) / (|n| (|n| − s)) + ε)`, the denominator a `Mag` lower bound (`from_exact_num_lower`, `mul_lower`, `sub_lower`); the midpoint is `ExactNum::div_exact` when the quotient is exact, else `div` rounded `ToEven`. The exact zero divisor `0 ± 0` is `Domain` (zenith-float's `DivisionByZero`, 10.4); a divisor ball reaching 0 (`|n| ≤ s`, including an infinite `s`) is all reals under both policies (10.3). `inv(self, prec)` is `round(1 / n) ± (s / (|n| (|n| − s)) + ε)` via `reciprocal`, with the same zero rules. `hypot(self, &Ball, prec)` is the monotone enclosure: hypot increases in `|x|` and `|y|`, so with `min|X|` = 0 when `|m| ≤ r` (decided exactly) else `|m| − r` rounded `ToZero`, and `max|X|` = `|m| + r` rounded `FromZero` (both at `prec + 64` bits, capped at `MAX_PRECISION`), `lo = hypot(min|X|, min|Y|)` rounded `Down` and `hi = hypot(max|X|, max|Y|)` rounded `Up` at `prec`; the result is `mid = round((lo + hi) / 2)` (`ToEven`) `± max(hi − mid, mid − lo)` with the differences exact and the `Mag` rounded up. The radius is at most the 1-Lipschitz `r + s` plus the endpoint roundings, and far below it when a ball reaches 0. A radius outside zenith-float's exponent range (including an infinite one) falls back to `round(hypot(m, n)) ± (r + s + ε)`. An overflowing endpoint or midpoint (+Inf) is all reals (10.4). A bad `prec` is `InvalidArgument` (8.1). Tests: `div_rows`, `div_by_zero_and_zero_straddling`, `inv_rows`, `hypot_rows`, `div_inv_hypot_overflow_and_prec`, `div_inv_wide_divisor_and_mid_rounding`, `div_inv_denominator_rounds_down`, `hypot_wide_rows_1313_1343_tight` (Harper's oracle rows 1313 and 1343, rad ≤ 4·RREF), `hypot_radius_covers_both_endpoints` and the 237 `div` rows of `enclosure_rows_contained`.
- **16.S1.10 abs, mul_2exp.** `abs(self, prec)`: when `|m| ≥ r` (decided exactly, as in 16.S1.7) the result is `round(|m|) ± (r + ε)`; a ball touching 0 is still exact (`[−2|m|, 0]` maps to `|m| ± |m|`). A straddling ball (`|m| < r`, or undecided) gives the endpoint ball `[0, |m| + r]` with the sum `add_up`; the all-reals input stays all reals. `mul_2exp(self, k: i64, prec)` is `ldexp(m, k)` at `prec`, `ToEven` (exact unless the midpoint has more than `prec` bits or leaves zenith-float's range: overflow is all reals, a deep underflow gets the bottom ε of 16.S1.2, a shallow one stays exact), and the radius `r · 2^k` with a checked `Mag` exponent (overflow `Infinity`, underflow the smallest positive `Mag`, exact otherwise). Tests: `abs_rows`, `mul_2exp_rows`, `exact_top_binade_midpoint_is_not_overflow` (an exact top-binade midpoint is not overflow, 10.4).
- **16.S1.11 Tri comparisons and overlaps.** One primitive computes `D = m1 − m2` and `R = r1 + r2` exactly (`sub_full_prec`/`add_full_prec`) and returns the signs of `D + R` and `D − R`; undecided only where the S2 comparisons (16.S2.1, 16.S2.2) leave it undecided: an `Infinity` radius, a NaN or inexact difference, or both radii outside zenith-float's range; undecided is `Unknown`, never `False`. `lt`: `True` iff `D + R < 0`; `False` iff `D − R > 0` or both are exactly 0 (two equal exact points); else `Unknown` (so touching edges are `Unknown` on either side). `le`: `True` iff `D + R ≤ 0`; `False` iff `D − R > 0`; else `Unknown`. `gt(a, b) = lt(b, a)`, `ge(a, b) = le(b, a)`. `eq`: `True` iff `D + R = D − R = 0`; `False` iff disjoint (`D + R < 0` or `D − R > 0`); else `Unknown`. `ne` negates `eq`. `overlaps`: `True` for an `Infinity` radius or `D − R ≤ 0 ≤ D + R`, `False` when disjoint, `Unknown` when undecided. Comparisons ignore `prec`. The methods are inherent on `Ball` in `src/arith.rs`. Test: `tri_compare_rows`.
- **16.S1.9 Tests.** The containment oracles bracket each true result at 128 bits finer than both the inputs and the target `prec`. The add/sub random operands keep their exponents within 200 of each other, because a wider gap only feeds ε and makes the exact oracle cost grow without bound.

### Slice S2 (`src/bridge.rs`)

Owner: slice S2 (Spence). Code: `src/bridge.rs`. Tests: `tests/harness/slice_bridge.rs`. Mutants 300-399. Scope moved in 2026-10-24: TEST_PLAN L0a-4, `Mag::cmp_exact_num` (clause 4.2), `Mag::cmp_exact_diff` (15.2, 10.2c), the `from_exact_num(_lower)` / `to_exact_num` sets and P9.

- **16.S2.1 cmp_exact_num.** `r.cmp_exact_num(x)` is `Some(r.cmp(|x|))`, decided exactly: Infinity is above every finite `|x|` (`Some(Greater)`); canonical zero against `±0` is `Equal` and against a nonzero `x` is `Less`, and a nonzero `r` against `±0` is `Greater`, by sign only (2.3, zero checks first); otherwise `(exp, mant)` of `r` against `x`'s exponent and top 64 mantissa bits, and on a tie a set sticky bit (any lower bit of `x`) puts `r` below. The sign of `x` is ignored. Exponents compare as i64, so a radius outside zenith-float's `EXPONENT_MIN..=EXPONENT_MAX` (an i64 range; 1-word subnormals reach down to `2^(EXPONENT_MIN − 64)`) compares correctly and is never converted. NaN or infinite `x` is `None`. Clause 4.2: `|m_b| ≤ r_b` is `r_b.cmp_exact_num(m_b) != Some(Less)`. **Callers map `None` to `Tri::Unknown`** (undecided, never `False`); `Ball` never holds a NaN/Inf midpoint (6.2).

Owner: slice S4b (Cassie). Code: `src/carlson.rs`. Tests: `tests/harness/slice_carlson.rs`. Golds: `tests/goldens/slices/carlson/` (`scripts/gen_carlson_goldens.py`). Mutants 600-699. - **LW.1** **16.S4b.1 API and errors.** `Ball::lambert_w0(&self, prec: Precision, policy: &DomainPolicy) -> BoundResult<Ball>` (principal branch, domain `[-1/e, inf)`, values in `[-1, inf)`) and `Ball::lambert_wm1(&self, prec, policy)` (branch -1, domain `[-1/e, 0)`, values in `(-inf, -1]`). A bound that cannot be certified within the working-precision cap is `Resource`, never an unchecked value. `-1/e` is not dyadic, so no finite input sits on the branch point: `x >= -1/e` is decided exactly by `x·e_hi >= -1` (inside) or `x·e_lo <= -1` (outside), with `e_lo < e < e_hi` the zenith-float `Down`/`Up` values of `e` at a doubling working precision; an input still undecided at the cap counts as outside.
- **LW.2** **16.S4b.2 Domain policy and enclosure.** With `lo = m - r` and `hi = m + r` (rounded outward when not exact; a radius below zenith-float's range is replaced by `2^(EXPONENT_MIN - 1)`, which only widens the ball): an all-reals input, or a radius above zenith-float's range, is `Domain` under `Strict` and all reals under `Clip`. `lambert_w0`: `lo` inside gives the ball enclosing `[W0(lo), W0(hi)]`; otherwise `Strict` is `Domain`, and `Clip` is `Domain` when `hi` is outside too and else encloses `[-1, W0(hi)]`. `lambert_wm1`: `hi >= 0` is `Domain` (`Strict`) or all reals (`Clip`, the image is unbounded below); otherwise `lo` inside gives `[Wm1(hi), Wm1(lo)]`, and when `lo` is outside `Strict` is `Domain`, `Clip` is `Domain` when `hi` is outside and else encloses `[Wm1(hi), -1]`. A midpoint `hi` beyond zenith-float's range gives all reals. Each endpoint value is certified, not trusted: a Newton estimate `w` at working precision `wp = prec + 64` gives candidates `w ∓ 2^(e(w) - prec - 8)`, accepted only when a directed-rounding test proves them on the right side, the precision doubling (to the cap `8·prec + 4096`) until they are. For `W0` at `x <= 4` the test is the sign of `w·e^w - x` (monotone for `w >= -1`; `e^w` rounded `Down` or `Up` as the sign of `w` needs, the product exact); for `W0` at `x > 4` and for every `Wm1` it is the sign of `ln|w| + w - ln|x|` (increasing on `w > 0` and on `w < -1`; `ln` rounded outward, the sums exact), so no `e^w` overflows at inputs up to `2^EXPONENT_MAX`. A `W0` lower candidate below `-1` is replaced by `-1` and a `Wm1` upper candidate above `-1` by `-1` (always valid bounds); `W0(0) = 0` exactly. The result is `mid ± rad` with `mid = round((L + H)/2, prec)` (`ToEven`) and `rad = max(H - mid, mid - L)` rounded up.

### LA refusal mapping (LA plan, 2026-10-24; shared by LA1 to LA5)

16.LA.1 Refusal reasons map to `BoundError` variants: `not_spd` and `sigma_not_spd` → `NotPositiveDefinite`; `singular` and `rank_deficient` → `Singular`, with the `detail` field naming which (`"singular"` or `"rank_deficient"`); `wide` → `DimensionMismatch`; `not_symmetric` → `NotSymmetric`. Exact LA golds: owner Cassie.

- **16.LA.2 Certified refusals (O11-W; CONTRACT LA, Spence 2026-10-29).** A value refusal (`NotSymmetric`, `NotPositiveDefinite`, `Singular`) is returned only when it is **certified** for the input ball: `NotSymmetric` when some pair `a_ij`, `a_ji` are disjoint balls (the ball holds no symmetric matrix); `NotPositiveDefinite` when a pivot ball has upper bound ≤ 0 after all earlier pivots were certified > 0 (then every symmetric matrix in the ball fails); `Singular` when an eliminated column, pivot or diagonal is exactly `0 ± 0` (every matrix in the ball is singular or rank-deficient), and in 16.S6.12 when a triangular diagonal ball contains 0 (the ball then holds a singular triangular matrix). A ball that reaches 0 without such a certificate is **undecided** and gives `Resource` with a static detail (`"undecided_pivot"`, `"undecided_det"`, `"undecided_rank"`, `"undecided_orthogonality"`). **Computed triangles:** whenever an LA op passes a computed factor (`G` or `H` of LA1/LA4, `U` of LA2, `R` of LA3) to 16.S6.12, it first classifies that factor's diagonal itself: exactly `0 ± 0` → the certified refusal of that op; a ball that contains 0 otherwise → `Resource "undecided_pivot"`. 16.S6.12's own `Singular` is certified only for the triangular ball it is given, not for the matrix the factor came from (outward rounding of `sqrt` or `div` can widen a factor diagonal to reach 0 even when every pivot was certified > 0), so a computed factor must never reach it with a diagonal that contains 0. `BoundError::detail` is `&'static str`, so the failing index is not reported. No new `BoundError` variant is added.
- **16.LA.3 Error order in LA ops.** First the three checks of 16.S6.3 in their order (`InvalidArgument` for `prec`, `DimensionMismatch` for shape, `Resource` for storage). Then `NotSymmetric` (checked over all pairs before any arithmetic). Then the first value failure in algorithm order (lowest step index): a certified refusal or an undecided `Resource`. `NotConverged` comes only from an iteration budget (`EigOpts::max_sweeps`). Values never give `InvalidArgument` or `DimensionMismatch`. An `Infinity` radius or a midpoint overflow gives all-reals entries as `Ok` (clause 10.4) wherever the op can still return a value, and a refusal only when 16.LA.2 certifies it: an all-reals pivot is undecided (`Resource`), never `Singular`. **Right-hand side length (Cassie review 2026-10-29).** In every LA solve (16.S6.12 `solve_*`, LA2 `solve`/`solve_mat`, LA3 `lstsq`, `BallCholesky::solve`), a `b` whose length (or row count) differs from the system dimension gives `DimensionMismatch` with detail `"b_len"`.
- **16.LA.4 Gold replay of refusal rows.** The LA golds are exact rationals, so the oracle names a refusal even where ball arithmetic cannot certify it at the row's `prec` (an inexact elimination step can leave a straddling ball). A replay row expecting `ERR <Variant> <detail>` passes on that error **or** on `Resource` with an `"undecided_*"` detail, **except** on the rows that are certified with exact arithmetic, which must return the named error: cholesky `zero2`, `onebyone_neg`, `onebyone_zero`, `indefinite2`, `psd_singular3`, `nonsym2`, `neg_def3`, and `nearsing_neg2` at `prec ≥ 201`; solve `zero*` and `dup_rows3`; qr `zero2` and `onebyone_zero`; gls `sigma_not_spd` and `sigma_singular`. The harness keeps this list as one constant per test file. A value where the gold expects a refusal always fails.
- **16.LA.5 Containment and tightness (Cassie review 2026-10-29).** **Containment (P0):** a replayed value passes when its ball contains the exact value. Containing the whole gold `[lo256, hi256]` interval is sufficient but not required. A ball that overlaps the gold interval without covering it is re-decided against the heavy `enc4096`/`enc16384` enclosures of the same row, and fails only if it still excludes them or is disjoint from `[lo256, hi256]` (clause 12.1: a ball that contains the exact value is correct, however narrow). **Tightness:** the generator emits a per-row bound `k_row = 4 + ⌈log2 n⌉ + ⌈log2 cond_row⌉`, where `cond_row` is the exact componentwise (Skeel) condition number of the row, including the growth from the exact `L` and `U`. The replay requires `rad ≤ 2^(k_row − prec)·max(|value|, scale_row)`, with `scale_row = 1` for ln outputs and `scale_row = ‖x‖_∞` for solve outputs. The bound is enforced only when `prec > k_row + 8`. Below that, and on rows the generator marks `containment_only` with a written reason (wrapping growth such as `2^n`), the replay checks containment only. The generator also writes the first-order componentwise reference `RREF` (exact rationals: `|ΔA| ≤ γ_n·|L|·|U|`, `Δ ln|det| = tr(A⁻¹ΔA)`) as a logged diagnostic column; it is not enforced. Mutants that only widen a radius are killed by the `k_row` bound where it is enforced and are otherwise allowed to survive with a written reason.
- **16.LA.6 Working precision (Cassie review 2026-10-29; LA0 to LA5).** Every LA op, and 16.S6.12, works at `w = prec + 64 + 2·⌈log2(n + 1)⌉`, capped at `MAX_PRECISION`. `w` is a deterministic function of `(prec, n)`. The result is rounded outward to `prec` once, at the end. There is no adaptive retry loop in 2.0. This follows the S1.6 and 16.S6.7 precedent.

### Slice LA5a (`src/eigen.rs`, symmetric)

Owner: Cassie, branch `cassie/zb-la5a-eigsym`. Code: `src/eigen.rs`. Tests: `tests/harness/slice_eigen.rs`. Golds: `tests/goldens/slices/eigen/` (`la_eig.txt`). - **16.LA5a.1 Signature.** `BallMat::eig_sym(&self, opts: &EigOpts, prec: Precision) -> BoundResult<BallVec>`. It returns `n` balls in ascending order: ball `i` encloses the `i`-th smallest eigenvalue of every symmetric matrix in the ball (read as in 16.LA1.2). Balls may overlap. Borrows.
- **16.LA5a.2 Errors (16.LA.3).** `prec`, non-square (`DimensionMismatch "rectangular"`), storage, then `NotSymmetric "a"` (disjoint pair). Cyclic Jacobi on the midpoint that has not met its stopping rule (off-diagonal Frobenius norm ≤ `2^-prec·‖M‖_F`) after `opts.max_sweeps` (default 64) → `NotConverged`. `δ ≥ 1` (16.LA5a.3) → `Resource "undecided_orthogonality"`. `opts.cluster` is accepted and has no effect in this version (open).
- **16.LA5a.3 Bound.** `M` is the exact midpoint matrix, symmetric (lower triangle mirrored). `R` is the radius matrix with its lower triangle mirrored (the same reading as `M`), and `ρ = norm_frob_up(R)`. `V` is the `prec`-bit point matrix from Jacobi. Soundness does not depend on how `V` was computed. (a) `δ ≥ ‖VᵀV − I‖₂` by `norm_frob_up` of the ball product `VᵀV − I` (16.S6.7). (b) `B ∋ VᵀMV` by two ball `matmul`s, `D = diag(mid B_ii)` (point), and `f ≥ ‖B_exact − D‖₂` by `norm_frob_up(B − D)`. Let `d_(i)` be the sorted `D`. (c) **Weyl** (`B_exact` is symmetric): `λ_i(VᵀMV) ∈ [d_(i) − f, d_(i) + f]`. (d) **Ostrowski** (`δ < 1`, so `V` is nonsingular): `λ_i(VᵀMV) = θ_i·λ_i(M)` with `θ_i ∈ [λ_min(VᵀV), λ_max(VᵀV)] ⊆ [1 − δ, 1 + δ]`. So `λ_i(M)` lies in the hull of `{y/t : y ∈ [d_(i) ± f], t ∈ [1 − δ, 1 + δ]}`, computed with outward rounding. (e) **Weyl again**: for every symmetric `A` in the ball, `|λ_i(A) − λ_i(M)| ≤ ‖A − M‖₂ ≤ ‖R‖_F ≤ ρ`. The result is ball `i` of (d) widened by `ρ`. Every step is either a theorem applied to exact symmetric matrices, or an enclosure from S1/S6. No residual-only (Bauer–Fike) claim is made. Gershgorin cluster refinement on `VᵀAV` (PLAN) is a later unit.
- **16.LA5a.4 Work and order.** At most `max_sweeps` sweeps of `n(n−1)/2` rotations, in row-major pair order, each a bounded S1 operation, so the work does not depend on exponent spread. An all-reals entry or overflow gives an all-reals `ρ` and all-reals balls, `Ok`.
- **16.LA5a.5 Replay.** Ball `i` must contain the gold's `[lo_i, hi_i]`. If it does not but overlaps it, the test decides containment of the exact root from the gold `charpoly` with an exact Sturm count over the ball's rational endpoints. Refusal rows go through 16.LA.4.
- **16.LA5a.6 Mutants 1400-1412:** 1400 `ρ` is dropped (midpoint eigenvalues only); 1401 `δ` is dropped (assumes `V` orthogonal); 1402 Ostrowski divides by `1 + δ` only (one side of the hull); 1403 `f` uses only the off-diagonal of `B`, without `B`'s radii; 1404 the output is not sorted; 1405 sorted descending; 1406 `NotSymmetric` uses midpoint inequality; 1407 running out of sweeps returns `Resource`; 1408 `δ ≥ 1` proceeds; 1409 `max_sweeps` is ignored (fixed 64); 1410 `ρ = norm_inf(R)`; 1411 `B = V·M·Vᵀ`; 1412 a non-square input is accepted.

### Slice CB (`src/cball.rs`)

Owner: slice CB (Cassie). Reviewed by Spence, 2026-10-24. Built on S1 (`spence/zb-s1`). Mutant block 1500-1599 (`tools/mutants/manifest.d/cball.txt`; S3 keeps the 400s).

- **16.CB.0 Dependency.** `CBall` uses only the public `Ball` API of `src/ball/mod.rs` and S1 (`add`, `sub`, `mul`, `sqr`, `div`, `hypot`, `mul_2exp`, `neg`, the `Tri` comparisons) and never S1 internals; it adds no radius arithmetic of its own. Ownership follows O9 (zf style): a binary op takes its first operand by value and borrows the second (`add(self, &Ball, prec)`, likewise `sub`, `mul`, `div`, `hypot`); CB's own ops do the same (`CBall::add(self, &CBall, prec)`), and a part is consumed where the inner op consumes it. CB never rebuilds or copies a part and adds no `*_ref` helpers. Pending upstream: S1 converts `sqr`, `inv`, `sqrt`, `hypot`, `powi`, `abs` to `&self` (SHA to follow), which `CBall::sqr` needs (it uses each part twice); `CBall::mul` and `CBall::div` use each part in two products and wait on borrowing once-rounded zf ops for `add`, `sub`, `mul`, `div`, `mul_2exp`, `neg` (Rusty, after R9). Until those land the three ops return `Resource` (`detail` names the wait) and their tests are `#[ignore]`d red.
- **16.CB.1 Representation.** `CBall { re: Ball, im: Ball }` denotes the closed rectangle `{x + iy : x ∈ re, y ∈ im}`. Fields are private; `CBall` is not `Clone`, `Copy`, `PartialEq` or `PartialOrd`; representation equality is `identical`. Invariants: (I1) each part satisfies clauses 6.1-6.5; (I2) `re.prec() == im.prec()`, else `CBall::new` returns `InvalidArgument`; (I3) parts are independent: an all-reals part does not make the other all-reals; a `CBall` is informative iff both parts are; (I4) the rectangle is the only form (no polar or disc form). Constructors `new(re, im)`, `from_real(re)` (`im = 0 ± 0`), `all_complex(prec)`; accessors `re`, `im`, `prec`, `into_parts`.
- **16.CB.2 Rounding.** Every part comes from a `Ball` op: midpoint to nearest (`ToEven`) at `prec`, radius outward (9.1); no `RoundingMode` parameter (O19), no extra ε. Guarantee for every op `f`: for every `z ∈ a` (and `w ∈ b`), `f(z[, w]) ∈ result`, by inclusion monotonicity of the composed `Ball` ops.
- **16.CB.3 neg, conj, add, sub.** `neg = (−re, −im)` and `conj = (re, −im)` are exact and infallible. `add`/`sub` = `(a.re ± b.re, a.im ± b.im)`, two `Ball` ops (9.3), exact when both are exact.
- **CB.4** **16.CB.4 mul.** Four-product form: `re = a.re·b.re − a.im·b.im`, `im = a.re·b.im + a.im·b.re`, each product `Ball::mul`, each combination `Ball::sub`/`add`. The 3-multiplication Gauss/Karatsuba form was considered and rejected (looser radii from dependency, cancellation in `re`, extra overflow in the pre-sums); it is not provided.
- **16.CB.5 sqr.** `re = sqr(a.re) − sqr(a.im)` with `Ball::sqr`; `im = mul_2exp(a.re·a.im, 1)` (exact doubling). Each part of `sqr(a)` is no wider than the matching part of `mul(a, a)` on every input (tested on every row).
- **16.CB.6 abs.** `abs(a, prec)` returns a real `Ball`: `Ball::hypot(a.re, a.im, prec)` as specified in 16.S1.8 (monotone, endpoint-based at `prec + 64`, lower endpoint ≥ 0), used as is. CB does no scaling of its own. A range gap of `hypot` at `i64`-exponent extremes is S1's: it is reported to S1 as a failing test, not worked around in CB. Overflow is the all-reals ball as `Ok` (10.4).
- **CB.7** **16.CB.7 div.** `a / b`: CB first chooses `k` from the larger part exponent of `b` and applies the same exact `mul_2exp(·, −k)` to all four parts of `a` and `b` (the quotient is unchanged); then `d = sqr(b.re) + sqr(b.im)`, `re = (a.re·b.re + a.im·b.im) / d`, `im = (a.im·b.re − a.re·b.im) / d`, each `/` `Ball::div`. Two all-reals cases, aligned with 16.S1.8 and 10.4 (Spence, 2026-10-24): in each, `cball_div` returns `Ok` with **both** parts all reals (`mid = +0`, `rad = Infinity`), never `Domain`. Both are decided exactly by CB before any `Ball::div`:
  - (R1) iff both `b.re` and `b.im` reach 0 (`|m| ≤ r`, decided exactly). Independent of `prec`.
  - (R2) iff R1 does not hold but `|b|²` cannot be certified clear of 0 at this `prec`: the computed `d` reaches 0 (`|d.mid| ≤ d.rad`, decided exactly). R2 is kept as a defensive check. Measured looseness (documented, not a bug): S1 `sqr` is mid-rad (16.S1.5, `rad = 2|m|r + r² + ε`), so for `b.re = 2^-40 ± 2^-41`, `b.im = 0` the computed `d` has `rad ≥ mid` and reaches 0 although `|b|² ≥ 2^-82`; that row returns all reals, and the test asserts exactly that observed behavior.
  Otherwise `div` encloses with finite parts (unless a part overflows). Overflow in `d` or a numerator gives an all-reals part as `Ok`. Known looseness (2.x): `a·conj(b)/|b|²` repeats `b` in numerator and denominator (dependency); a tighter quotient hull is out of scope for v1.
- **16.CB.8 Errors.** No new variant. `InvalidArgument` (`prec == 0`, part precisions differ), `Representation` (via `Ball` constructors), `Domain` and `Resource` only as propagated from an inner `Ball` op (CB itself raises neither; `cball_div`'s R1 and R2 are all-reals `Ok` results, 16.CB.7). An inner `Ball` error is returned with `op` set to the `cball_*` op name and its `detail` kept. Overflow is never an error (10.4).
- **CB.9** **16.CB.9 Precision, NaN and Inf.** One `prec` per call, used by every inner op; both output parts carry it. No internal precision boost. No NaN or Inf is ever stored (6.2). An unbounded part is all reals as `Ok`; in `mul` and `div` an all-reals input part makes every output part that uses it all reals. No complex infinity, no branch cuts.
- **CB.10** **16.CB.10 Golds and tightness.** Golds are `mpmath.mpc` point references (mpmath 1.3.0) at `4·prec + 64` bits, from `scripts/gen_cball_goldens.py` pinned as the other slices. They are checked by containment: the result must contain the reference for sample points of the input rectangles (corners, midpoints, random interior points). mpmath `iv` has no complex intervals; no interval gold is claimed. Tightness is checked per part against `RREF`, the first-order radius computed in mpmath at the same precision (the sum of `|∂f/∂x|·r` over the input parts at the midpoint, plus `2^(e − prec)` for the result's rounding). Stated factors: `neg`, `conj` exact (rad equal to input); `add`, `sub` ≤ 2·RREF (RREF already carries one ulp); `mul` ≤ 2·RREF; `sqr` per part ≤ 2·(RREF + S2) and ≤ the `mul(a, a)` radius, where S2 is the second-order term RREF omits (exact from the input radii r_re, r_im: re part r_re² + r_im², im part 2·r_re·r_im), since a first-order RREF cannot cover `re²` when r_re is not small (ruling Spence 2026-10-25, resolves the 16.CB.10 sqr item); `abs` ≤ 4·RREF (the 16.S1.8 bound); `div` ≤ 8·RREF when `d` is clear of 0 by at least half its value, otherwise containment only (gold `div` rows are drawn in that region).
- **16.CB.11 Tests.** `cball_construct_invariants`; `cball_add_sub_neg_conj_rows`; `cball_mul_rows` (cancellation, mixed signs, parts containing 0); `cball_sqr_rows` and `cball_sqr_not_wider_than_mul` (every row); `cball_abs_rows`; `cball_abs_i64_extremes` (red for S1 if `hypot` has a range gap); `cball_div_rows`; `cball_div_rectangle_containing_zero_is_all_reals` (R1, edges `|m| = r`); `cball_div_mid_rad_sqr_widening_is_all_reals` (R2, the measured row above); `cball_div_scaling_exact`; `cball_all_reals_propagation`; `cball_prec_sweep` (`prec ∈ {1, 2, 53, 64, 113, 256, 1024}`); `cball_golden_rows_contained`; `cball_tightness_factors`.

## Open clauses (none remain; O18-C is listed here with its decision)

As of 2026-10-16 every former open item (O1, O6, O11-C to O14-C) is decided and lives in the Decisions table. Nothing in this section is open. `O11-C` to `O14-C` were Cassie's items (the `-C` suffix avoided a clash with the worker's O11).

- **O18-C Operand-valued results and the zero-copy rule (DECIDED: Jeff, via Paul, 2026-10-16; raised by Rusty's review of L0a).** `add_up(0, b) = b`, `add_up(a, 0) = a` and `sub_lower(a, 0) = a` (clause 2.3) return a value equal to an operand, while `Mag` has no `Clone` or `Copy` and every `Mag` method takes `&Mag` (clause 15.1, O9). **Decision:** a `Mag` may be rebuilt from its two scalar integers with `Mag::from_canonical(exp, mant)`, where `(exp, mant)` come from the private `Mag::nonzero()`, while all methods keep their `&Mag` signatures. No `Mag -> Mag` copy function exists (the former `Mag::replicate` is removed). The by-value alternative (`Mag::add_up(self, other: Mag)`, `Mag::sub_lower(self, other: &Mag)`, which would have amended O9 and 15.1) is dropped; the branch `spence/zb-l0a-mag-green2-byvalue` stays unmerged. The independent oracle in `tests/model/direct.rs` follows the same rule (its former field-wise `dup` helper is removed; the zero-operand results are rebuilt from the integer parts with `MagV::Finite { exp: i64::try_from(e).ok()?, mant: u64::try_from(m).ok()? }`). `tools/rules_scan.sh` enforces the decision with two ratcheted counts that may only go down and have no allowlist: `hidden_copy_count` (copy-shaped functions in `src/`, `tests/`, `benches/` and `examples/`, baseline 0) and `sanctioned_rebuild_count` (`Mag::from_canonical(..)` call sites in `src/` fed by a part of another value, baseline 2: `add_up` and `sub_lower`). A third rebuild fails the gate until Jeff approves a baseline raise.
