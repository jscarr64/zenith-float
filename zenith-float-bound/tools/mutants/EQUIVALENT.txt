018-L4	src/mag/lower.rs sub_wide, `Ok(shift) if shift < 64` -> `< 63`. The arms now differ only at shift == 63, where the real code subtracts k = 1 + frac (frac = low 63 bits of mb nonzero) and the mutant k = 1. sub_wide rounds down and diff = ma*2^63 - k with 1 <= k <= 2^62: if ma > 2^63, diff >= 2^126 so 63 bits are dropped and the mantissa is floor((ma*2^63 - k) / 2^63) = ma - 1 for every such k; if ma == 2^63, diff < 2^126 so 62 bits are dropped and the mantissa is floor((2^126 - k) / 2^62) = 2^64 - 1 for every such k. The exponent is the same in both. So k in 1..=2^62 is unobservable (only shift == 1, where k can exceed 2^62, is observable). Before the guard was tightened this mutant was `< 128 -> <= 128` and was killed by the `u128::MAX << 128` overflow, which no longer exists. Checked by a Python model of sub_wide + norm (200k random and edge ma, mb at shift 62..64: 0 differences).
019-L5	src/mag/lower.rs sub_wide, `Ok(shift) if shift < 64` -> `< 65`. The two arms differ only at shift == 64 (shift >= 1 because gap >= 64). In the shifted arm with shift == 64: `mb >> 64` is 0 (mb < 2^64) and `frac = (mb & !(u128::MAX << 64)) != 0` is `mb != 0`, because the mask keeps the low 64 bits and mb < 2^64 lies inside them; mb is a NonZeroU64, so frac is true. The `_` arm returns (0, true). Same pair, so the same `diff`, the same result. The same holds for every shift in 64..=127, so no threshold in that range is observable; `< 64` is the smallest guard for which every shift it sends to `_` gives (0, true) (at shift 63, mb >> 63 == 1).

144-C-wpguard	src/enclosure.rs working_prec, guard `GUARD_BITS` -> `GUARD_BITS - GUARD_BITS` (0). The working precision is still p = max(prec(mid), prec(x), 64) >= prec(x), so -x stays exact. hi = mid + (-x) rounded Up at p, then Mag::from_exact_num rounds Up again to the Mag's 64-bit mantissa; lo the same with Down and from_exact_num_lower.
