# Slice S1 documented equivalent mutants (format as ../EQUIVALENT.txt). Starts empty.
216-PREC	check_prec accepting prec 0 is unobservable: every arith result is built by Ball::exact/from_mid_rad/all_reals, which reject prec 0 with the same InvalidArgument (prec_out_of_range_is_invalid_argument passes either way)
227-CLEARTOUCH	clear_of_zero accepting |n| == s is unobservable: n_lo <= |n| = s so n_lo.sub_lower(s) is 0, the denominator is 0 and Mag::div_up by 0 is Infinity (0/0 included, CONTRACT 14.1), so from_mid_rad returns the same all-reals ball
228-CLEARINF	dropping the s.is_infinity() guard is unobservable: s.cmp_exact_num(n) on an Infinity s is Some(Greater) (16.S2.1), reversed to Less, so clear_of_zero is None either way
255-ABSEQ	sending |m| == r to the straddle branch is unobservable: finish(round(|m|), r) and endpoint_ball(|m| + r) both give [0, 2|m|] with the same rounding (probe on HEAD vs mutant, |m| = r = 2^63-1 at prec 2/8/32, identical mid and rad; logs 2026-10-24 *-probe-head2.log / *-probe-255b.log)
264-M2ERR	the unwrap_or_else fallback is unreachable: mant comes from r.mant() (already canonical, no normalization shift) and ne is any i64, so Mag::finite(mant, ne) never errs
206-SQRLOST	src/arith.rs Ball::sqr, `let lost = sq.inexact()` -> `false`. `lost` is false because the square is exact at the pin: since zf 0cfee92 (CHANGELOG "the mantissa now grows by the shift first, so the result is exact"; helper `widen_for_subnormal` doc "A full-precision result below the normal range keeps every bit ... A shift past `MAX_PRECISION` cannot be kept and is rounded by `subnormalize` as before"), a square below EXPONENT_MIN keeps every bit with inexact() == false, and past MAX_PRECISION it is rounded and flagged inexact, which round_to flags too. The rounding of the exact square to prec reports inexact, so eps gives 2^EXPONENT_MIN; harper_edges `sqr_below_zf_range_is_not_exact` pins both the exact square and the non-exact ball.
